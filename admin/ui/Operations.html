▤ Current rules

Set in shared/Config.gs. Changing any of these is a code edit and a redeploy — deliberately, because they are the guardrails.

? When something looks wrong

  1. Nothing is sending. Check the kill switch on the Health tab, then whether the sender shows a recent heartbeat. No heartbeat means the agent's trigger is gone — the exec re-runs Onboard.
  2. A send failed. Health → Recent failures shows the verbatim error and how many attempts were made. Transient errors retry with backoff; a bad address fails immediately and permanently.
  3. Sends are queued but not going out. Almost always the send window: the agent refuses to send outside 09:00–17:00 on business days regardless of what was scheduled. Seed sends are the exception and go immediately.
  4. Timing is off by a few minutes. Expected. Gaps are accurate to about one poll interval.
  5. Replies are not being detected. Expected while the Gmail API is unavailable — see docs/GCP_CONSTRAINT.md. Record opt-outs manually on the Audience tab.
  6. Something needs a code change. node test/qa.mjs must pass, then scripts/sync-shared.sh, then clasp push and redeploy the existing deployment id. Never create a new deployment — the URL would change and the agents would stop finding the gateway.
